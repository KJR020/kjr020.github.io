ここ数ヶ月ほど生成AIを活用したシステム開発のPoCに取り組んでいます。
開発するシステムの要件が固まっていない状態で、UXも含めて提案する役割を任された事がきっかけでUX設計を学んでいます。

生成AIを使うと、それらしいUIは短時間で作れます。一方で、「なぜこの画面が必要なのか」「なぜこの情報をここに置くのか」といった設計は、別に考える必要があると感じました。

UXについて体系的に学ぶ中で知ったのが、Jesse James Garrettの『The Elements of User Experience』です。今回は、本書の中心的なアイデアである5つのレイヤーについて、自分なりの理解をまとめます。

## The Elements of User Experience

『The Elements of User Experience』は、個別の作り方や技術ではなく、UX設計で何を考えるのか、その全体像を扱った本です。ギャレットは本書について、正解を示す本ではなく、適切な問いを考えるための本だと語っています[^1]。

日本語版は『The Elements of User Experience 5段階モデルで考えるUXデザイン』というタイトルで、2022年に刊行されています。

<https://book.mynavi.jp/ec/products/detail/id=129696>

### そもそもUXとは？

UXの5段階モデルについて説明する前に、「そもそもUXってなんだっけ？」という話から整理します。
本書では、UXは製品やサービスの内部の仕組みではなく、人がそれらに触れたときに、どのように働き、どう感じるかに関わるものとして説明されています[^2]。

UXは画面の見た目やUI上の操作に限らず、使う人が製品やサービスと接する体験全体を扱うものとされています。

[ISO 9241-210:2019](https://www.iso.org/standard/77520.html)では、UXを「システム、製品またはサービスの利用、または利用を予期したことから生じる、ユーザーの知覚や反応」と定義しています（筆者訳）[^3]。
つまりUXは、画面そのものだけでなく、利用前の期待や、利用中・利用後に生じる認識や感情まで含む概念だと理解しました。

### ギャレットの5段階モデル

ギャレットの5段階モデルを設計プロセスとして捉えるのは正確ではない、という指摘は、[『オブジェクト指向 UI デザイン』に書かれていないもの](https://note.com/nikonote/n/n072c5ba6cc4b)を読んで知りました。
自分はUXデザインの専門家ではないため、この記事をきっかけに、できるだけ原著の表現に沿って理解したいと思いました。

原著では、この5つのレイヤーはUXの問題と解決手段について考えるための *conceptual framework* と表現されています[^4]。そのためこの記事では、順番に進める「工程」というより、UX設計で扱う問題を整理して捉えるための「見方」に近いものとして理解しています。

以下は、ギャレットが公開した5つのレイヤーの図です。

![Jesse James GarrettによるThe Elements of User Experienceの図](/images/posts/ai-era-user-experience-design/elements-of-user-experience.png)
*出典: Jesse James Garrett, [The Elements of User Experience](http://www.jjg.net/elements/pdf/elements.pdf), 2000（PDFを画像化、2026年8月6日確認）*

レイヤー間の依存関係について、原著では次のように説明されています[^4]。

> The choices you make on each plane affect the choices available to you on the next plane above it.

下にあるレイヤーでの判断は、その上のレイヤーで選べることに影響します。
何のために作るかが曖昧なら、必要な機能を判断しにくくなります。
必要な機能が定まっていなければ、画面遷移や情報構造の判断にも影響します。

## 5つのレイヤーで扱うこと

5つのレイヤーは、下から戦略・要件・構造・骨格・表層の順に並びます。下に行くほど抽象的で、上に行くほどユーザーが実際に触れる具体的な表現に近づきます。

ただし、下から上へ一方向に進めるわけではありません。各レイヤーの検討は重なり、上にあるレイヤーを考える中で、下にあるレイヤーの判断を見直すこともあります。

### 戦略レイヤー

戦略レイヤーで扱うのは、プロダクトの目的とユーザーのニーズです。

![ギャレットの図から戦略レイヤーを抜粋](/images/posts/ai-era-user-experience-design/elements-strategy.png)
*前掲図から戦略レイヤーを抜粋*

「このプロダクトで何を達成したいのか」という作る側の目的と、「ユーザーは何を求めているのか」というユーザー側のニーズの両方を整理します。つまり、「そもそも、なぜ作るのか」を考えるレイヤーです。

本書では、プロダクトの目的を具体化するものとして、成功指標についても扱っています[^5]。目的を言葉にするだけでなく、何をもってその目的を達成できたと判断するのかまで考えます。

### 要件レイヤー

戦略レイヤーで整理した目的やニーズを、「では、そのために何を提供する必要があるのか」という具体的な機能やコンテンツへ落とし込むのが要件レイヤーです。

![ギャレットの図から要件レイヤーを抜粋](/images/posts/ai-era-user-experience-design/elements-scope.png)
*前掲図から要件レイヤーを抜粋*

本書では、ユーザーのニーズとプロダクトの目的を具体的な要件へ翻訳することで、戦略が要件になると説明されています[^6]。

例えば、「ユーザーが自分に合った商品を選べるようにする」というニーズがあるなら、そのために必要な比較情報や絞り込み機能などを要件として考えます。

このように、戦略レイヤーが「何を達成したいのか」を扱うのに対して、要件レイヤーでは「そのために何が必要なのか」まで具体化していきます。また、要件を明確にすることは、何を作るかだけでなく、何を作らないかを明らかにすることにもつながります[^7]。


### 構造レイヤー

要件レイヤーで必要な機能やコンテンツを挙げただけでは、ユーザーがどのように操作し、情報をたどるのかまでは決まりません。

![ギャレットの図から構造レイヤーを抜粋](/images/posts/ai-era-user-experience-design/elements-structure.png)
*前掲図から構造レイヤーを抜粋*

構造レイヤーでは、要件として挙げた機能やコンテンツをどのようにつなぎ、組み立てるかを考えます。本書では、機能としての側面をインタラクションデザイン、情報としての側面を情報アーキテクチャとして扱っています[^8]。

インタラクションデザインでは、ユーザーが取り得る行動と、それにシステムがどう応答するかを設計します。

情報アーキテクチャでは、ユーザーが必要な情報を理解し、たどれるように、コンテンツを分類・整理し、その関係を設計します。

総じると、構造レイヤーでは、要件レイヤーで考えた必要な機能やコンテンツを「どのようにつなげるか」を考えるレイヤーになります。

### 骨格レイヤー

構造レイヤーで扱う機能や情報のつながりを、ユーザーが実際に操作・理解できるよう、画面上の配置として考えるのが骨格レイヤーです。

![ギャレットの図から骨格レイヤーを抜粋](/images/posts/ai-era-user-experience-design/elements-skeleton.png)
*前掲図から骨格レイヤーを抜粋*

ここでは、どこにボタンを置くか、どの情報を近くに配置するか、どのように画面間を移動できるようにするか、といった具体的な配置を考えます。

本書では、インターフェースデザイン、ナビゲーションデザイン、情報デザインの3つを扱っています[^9]。

- インターフェースデザイン
  - ユーザーが機能を使うためのボタンや入力欄などを配置する
- ナビゲーションデザイン
  - 情報構造の中を移動するための手段を配置する
- 情報デザイン
  - 情報が効果的に伝わるように整理し、提示する

本書では、この3つを一つの画面上にまとめる資料としてワイヤーフレームが紹介されています。ワイヤーフレームは完成後の見た目を示すものではなく、画面に何を置き、それらをどのように配置するのかを表します。

### 表層レイヤー

最も上にある表層レイヤーでは、骨格レイヤーで扱う配置を、色やタイポグラフィ、コントラストなどを使って、ユーザーが知覚できる視覚表現として具体化します。

![ギャレットの図から表層レイヤーを抜粋](/images/posts/ai-era-user-experience-design/elements-surface.png)
*前掲図から表層レイヤーを抜粋*

本書では感覚デザインとして扱われ、Webサイトでは主に視覚表現が中心になります[^10]。

どこへ注意を向けてもらうのか、どの情報がひとまとまりなのか、何が重要なのかといったことを視覚的に伝えます。

そのため、表層レイヤーは単に見た目を整えるものではありません。下のレイヤーで定めた目的や構造を、ユーザーが適切に理解できるように視覚表現で支える役割を持ちます。

## 読んでみての感想

ここからは、私の感想と、実際にPoCで5つのレイヤーを手がかりにUX設計に取り組んだ所感です。

生成AIでモックを作っていると、「それっぽいけど、なんか違う」という状態によくぶつかります。デザインシステムを用意して参照させることで、色やコンポーネントには、ある程度の統一感を持たせられました。

一方で、画面単体ではそれらしく成立していても、画面の目的や前後のつながり、何を強調するのかといった設計意図が一貫しないことがありました。生成されたUIからは、「なぜこの画面が必要なのか」「なぜこの情報がここにあるのか」といった設計上の理由を見いだせないこともあります。そのため、見たときに違和感はあっても、何が問題なのかをうまく言語化できず、「なんか違う」としか言えないことがありました。

その違和感を整理する手がかりになったのが、今回取り上げた5つのレイヤーです。画面の目的が曖昧なら戦略や要件、前後の体験や情報のつながりが弱ければ構造、配置や強調の仕方に問題があれば骨格や表層、というように分けて考えられるようになりました。

すべてをきれいに切り分けられるわけではありません。それでも、自分が今どのような問題について考えているのかを捉え直す軸として役立っています。

今回のPoCでは、生成AIによってUIを具体化する速度が上がりました。だからこそ、その背後にある「なぜ作るのか」「何が必要なのか」「どうつながるのか」は、自分たちで意識して設計する必要があると感じています。月並みな結論かもしれませんが、本書を読み、実際の画面と照らし合わせる中で、その実感が強まりました。
